Goal

Daimyo's kabuto must be built around his frog's dome eyes — a construction no image model has a training prior for, and one that changes head geometry, so it has to be right in the base image of his lineage before any concept or turnaround work can proceed (team brief §9's exemplar plan). This round generates that construction two ways and lets the human pick the winning geometry, which becomes the reference asset every later Daimyo round conditions on. It also settles, with data, whether isolating a hard head construction beats hunting it inside full-character rolls — a question Kage's hood (the other prior-less head construction) will reuse.

How the round is judged

Subjective machine image judgements are ADVISORY evidence for the human eye-call, which is the source of truth (standing policy, Dimitri 2026-08-22).

  • FAST: deterministic decode/aspect screens, then a fresh-context crop audit per artifact as it lands — mandatory 2x-upscale crops of the helmet and eye-dome region, plus (Arm B) hands, feet/ground contact, and the daishō side read as relations per the skill's chirality protocol. Once all ten fast results are logged, the provisional panel is shared.
  • SLOW: one blind_detect_round.py manifest over all ten artifacts (two Batch waves; run id recorded in rounds.md; recovery only via --resume-run). Any INCOMPLETE (provider-truncated) record satisfies completeness but carries no verdict and must be named in reconciliation; a mattering artifact gets a fresh sync blind_detect.py re-check appended as an additional record. Every crop-vs-blind disagreement is a mandatory human look.
  • Human gate: Dimitri (Jawaknight welcome) picks the winning kabuto construction. The primary criterion is the helmet-to-eye-dome geometry: readable frog eyes integrated into an engineered helmet, printable bold forms, flat-fan maedate, no human-helmet-perched-on-head read. Secondary, for Arm B only: whether the winning roll is also usable as the concept lineage base (pose, proportions, daishō placement — check specifically that the extended halt-arm does not occlude the saya, which share its viewer side). Two named trade-offs for the reviewer: Arm A's front three-quarter camera may drift toward profile (the measured profile-pull attractor) and occlude the far dome eye — an Arm A winner must show both eye housings readably — and an Arm A winner's ~30° camera will not match the straight-on front camera of later full-figure work (an img2img reference holds best for its own camera), acceptable for a construction exemplar but worth weighing against a clean Arm B roll. Reject-all with fresh direction is a fully valid outcome.

The provisional artifact starts eye-review but cannot close the round, promote a keeper, or authorize downstream work or spend. No waiver of the slow lane is proposed.

Before the panel may refresh to COMPLETE, two conditions hold together: the detector run's own final summary must report a fully finalized run — any PARTIAL finalization (a hard-error comparison appended no record, whatever artifact it names) stops for reconciliation in rounds.md regardless of the set check below — and the run's record set must equal the ten planned artifacts exactly:

T=projects/martial-frogs/daimyo
DETECT_RUN=<blind-detect run id recorded in rounds.md>
python3 - "$T" "$DETECT_RUN" <<'PY'
import json, sys
t, run = sys.argv[1], sys.argv[2]
planned = set(json.load(open(f"{t}/runbooks/r1-generation.json"))
              ["planned_artifact_ids"])
got = set()
for line in open(f"{t}/reviews.jsonl"):
    if not line.strip():
        continue
    r = json.loads(line)
    if r.get("reviewer") == "blind-detect" and r.get("batch_run_id") == run:
        got.add(r["artifact"])
missing = sorted(planned - got)
unexpected = sorted(got - planned)
assert got == planned, (
    f"blind-detect record set mismatch — missing: {missing}; "
    f"unexpected: {unexpected}")
print(f"blind-detect exact-set OK: {len(planned)} artifacts")
PY
