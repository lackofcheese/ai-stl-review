Goal

Meshy released its next-generation meshy-7 model (2026-08-12) on the same multi-image endpoint the pipeline uses, claiming higher-fidelity geometry than Meshy 6. R18 left us an unusually strong measuring stick: 12 rolls per clay arm on approved inputs, with per-arm watertight rates and sail verdicts recorded. This round reruns those three arms with the model as the single changed variable — identical inputs, identical settings — to measure whether meshy-7 moves exactly the defects r18 quantified: the non-watertight rate, stray second shells, and bent/doubled/detached sails. It also pins meshy-7's real credit price from the first task's billing, and its outcome decides whether meshy-7 becomes the pipeline's default reconstruction model.

12 rolls total — 3 choices, 4 + 4 + 4

Three cases × 4 rolls = 12 Meshy calls. The 360-credit cap prices every roll at the conservative 30-credit preflight ceiling, because Meshy has not published meshy-7 pricing yet; at meshy-6 parity the actual cost is 20/roll = 240 credits, and each task's provider-reported consumed_credits reconciles the ledger to actuals automatically. The 3,210 credits live at drafting are the WHOLE month's budget (Dimitri, 2026-08-11), so this round spends at most ~11% of it. python3 - <<'PY'
import pathlib, sys

bad = []
for arm, ext in (('bright-grokq', 'png'), ('bright-flash31', 'png'), ('orig-grokq', 'png')):

sys.exit(f'identity gate FAILED: {bad}' if bad else 0)

2b — Per-arm waves, sequential (the rest of the paid spend)

Run the three bounded manifests ONE AT A TIME, starting each only after the previous run PROVES FINALIZED — never concurrently (each stays ≤ 4 pending tasks, far below the ~30-task account queue ceiling that rejected 14 r18 creates). The coordinator's CLI exits 0 even when a run ends PARTIAL (a task hit REJECTED/FAILED/CANCELED/EXPIRED), so the gate between waves must inspect the recorded run state, not the exit code. The coordinator runs under python3 -u: piped through tee, a block-buffered stdout could hold the Meshy manifest run: line — the only recovery handle — past an abrupt kill; unbuffered, the id reaches $RUN_LOG and the console the moment the run exists, before the long polling phase. Record it in rounds.md as soon as it prints, not at wave end:

set -euo pipefail
for W in a1 a2 a3; do
  RUN_LOG=$(mktemp)
  python3 -u tools/meshy_manifest.py run \
    --manifest "projects/treeman-windmill/notes/r20-meshy-wave-$W.json" \
    --drive-sync | tee "$RUN_LOG"
  RUN_ID=$(sed -n 's/^Meshy manifest run: //p' "$RUN_LOG")
  # Record the run id in rounds.md immediately, before the next wave.
  python3 tools/meshy_manifest.py status --run "$RUN_ID" | python3 -c '
import json, sys
state = json.load(sys.stdin).get("state")
sys.exit(0 if state == "FINALIZED" else f"wave ended {state}, not FINALIZED — STOP")'
done
# After any interruption:
# python3 tools/meshy_manifest.py resume --run RUN_ID --drive-sync
# Never re-run a manifest.
