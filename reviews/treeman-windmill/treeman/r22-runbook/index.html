Goal

R20 asked whether Meshy-7 should replace Meshy-6 as the reconstruction model, and handed back a benchmark that cannot answer the printing half of the question. The raw meshes were checked in provider units, so nothing yet says how they behave at the 50 mm size Treeman actually prints at.

This round puts all twelve R20 rolls into millimetre coordinates with the same no-surgery placement R19 and R21 used, then runs the same battery those rounds ran, so Meshy-7 and Meshy-6 are compared on identical measurements at identical scale. It adds one screen the earlier battery did not have: how much of each mesh's tunnel topology survives when the mesh is resolved coarsely and then progressively closed.

That addition is the point. Meshy-7 carries about 75–85 tunnels per mesh where Meshy-6 carried 7–15, and the raw count alone cannot tell a sub-resolution reconstruction pinhole — which fills in as a blob and inflates supports — from a deliberate millimetre gap in weathered bark or a sail lattice. The first is a real cost of the new model; the second is the detail we wanted from it. How fast each model's topology disappears under coarsening separates those two readings without ever resolving an individual tunnel. Nothing in this round changes any geometry.

The measurement is comparative, and the round is careful about what it can conclude. No figure the probe reports is a count of tunnels: each is an aggregate topology count of the mesh reduced to a voxel grid, and any such reduction can invent topology as well as remove it — closing the gap between two crossing twigs joins them into a ring and creates a tunnel that was never there. What the round can say is how Meshy-7 compares with Meshy-6 when both are measured identically, which is exactly the question R20 left open. A 60-handle gap between the two models is far larger than the measurement's slack. What it cannot say, and will not claim, is "N tunnels on this mesh are below 0.1 mm".

How the round is judged

Every check is FAST — local and deterministic — so there is no slow lane and no provisional/complete split. The round produces measurements; it selects nothing.

  • Source identity: each of the twelve raw R20 STLs must match the SHA-256 pinned in the technical plan before anything reads it.
  • Placement contract: each output is uniformly scaled to 50.00 mm overall Z height, centered in X/Y, and moved so minimum Z is zero. The operation reports the exact uniform scale.
  • Geometry preservation: face and component counts, winding, and main-shell edge topology must match each source, and an independently derived source-to-output affine comparison must stay within 0.0001 mm. The known microscopic shards must be preserved and disclosed, never silently filtered — eleven of the twelve rolls carry one to five shards of 1–4 faces each, and A1 M3 and A3 M3 additionally carry one non-manifold edge on the dominant shell. Those are source facts and stay visible in the reports.
  • Final-scale evidence, per mesh: dimensions and volume, topology in millimetre units, the banded surface-roughness profile, the 0.28 mm-pitch thin-connection probe both ungolded and diffed against that arm's Meshy-6 reference, the global fragility index, and the grid handle screen.
  • Comparison: every measure is reported beside the same measure on the held Meshy-6 references at the same scale. Where a measure exists in the frozen R19/R21 reports it is read from them rather than recomputed, so the baseline cannot drift.
  • Handle screen specifically: voxel pitch 0.1 mm with closing diameters 0.2, 0.4, 0.6, 1.0 and 1.6 mm, identical for every mesh including the held Meshy-6 references, since the numbers are only comparable within one setting. Every figure the probe reports is an aggregate topology count of the voxel grid — handles in the grid, then handles after closing at each diameter — and none is a count of tunnels or identifies an individual feature. The round reports them as a Meshy-7-vs-Meshy-6 comparison and states that limit in the write-up rather than in a footnote.
    • Nothing is derived from the meshes' own genus. That is deliberate and matters here: only 1 of the 12 R20 meshes and 2 of the 4 Meshy-6 references are whole-file watertight, so a mesh-side figure would be undefined on most of the set and, worse, asymmetrically so across the comparison. The grid is well-posed on all sixteen — every dominant shell has zero open edges, the extra components being 1–4 face shards.
    • The applicability check is the round's, not the tool's. The probe asserts no validity verdict: it reports fill_ratio and leaves the judgement to the caller. The counts only mean something if the voxel fill reconstructed a solid rather than a shell, so this round makes that an explicit, recorded gate of its own, applied to each of the sixteen meshes before any comparison is drawn:
      1. Every mesh's fill_ratio must exceed 5.0. A leaked fill sits at 1.0; a 50 mm reconstruction of this character sits near 21. The threshold is far below the expected value and far above the failure value, and is a screen for a leak rather than a calibrated quantity.
      2. The sixteen ratios must cluster. Any mesh below half the median of the set is treated as anomalous even if it clears the floor above.
      3. Independently of the probe, each mesh's committed validation record must show a closed dominant shell (main_component_open_edges == 0). That holds for 12/12 R20 meshes and 4/4 Meshy-6 reference sources today, so it is a check that can fail rather than a restatement. A failure of any of the three stops the comparison for investigation and is recorded in rounds.md; it is never written up as a zero or quietly dropped. All three are cheap and are run before the arm-level comparison.
    • topology_creation_detected is recorded per mesh. This character is a likely trigger — crossing twigs and the sail lattice put surfaces within a millimetre of each other — so the round expects the flag to fire on some rolls, especially at the wider diameters, and treats that as a property of the geometry rather than a failure. Where it fires, that mesh's sweep is reported with the flag beside it and is not read as tunnel sizes at all. The flag is a necessary condition only: a creation cancelled by a fill at the same radius still reads monotone, so an unflagged sweep is evidence, not proof.
    • The round therefore cannot conclude "N tunnels are below 0.1 mm on this mesh", and no result statement may be written that way. It can conclude that one model's meshes carry substantially more or less grid topology than the other's, and shed it faster or slower under closing, under identical measurement — which is what the open R20 verdict needs.
  • Probe applicability: all twelve dominant shells have zero open edges, so the voxel fill the thin-part and handle probes depend on is well posed on every mesh. If a fill nevertheless leaks on any roll, that roll's handle numbers are recorded as unavailable with the evidence, not reported as zero.
  • Fresh-context comparative audit: one subagent walks a complete feature checklist over matched views of the Meshy-7 and Meshy-6 renders. It is a static pre-filter and picks no keeper.
  • Human gate: Dimitri's live-3D benchmark verdict on R20 remains the decision. This round supplies evidence for it and does not close it.

Technical plan

placement, battery and handoff

What changed going in
  • The battery is R19's, unchanged, extended to twelve meshes and given one new measurement: tools/mesh_handles.py. That tool did not exist for R19 or R21 and lands in its own reviewed PR (#481) before this round runs. Its merge-gate review narrowed what the closing sweep may be claimed to show; this plan is written against that narrowed contract, not the original one.
  • The thin-connection probe additionally runs with --gold against the same-arm Meshy-6 reference. R19 and R21 ran it ungolded, which reports every structural neck the body legitimately has; diffing against the arm's own Meshy-6 mesh suppresses those and isolates necks Meshy-7 introduced. Both forms are run, so the ungolded numbers stay directly comparable with the frozen R19/R21 reports.
  • Renders use the eight-direction compass set Dimitri asked for in R21, not R19's four azimuths, so Meshy-7 rolls and the held references are inspected at matched views.
  • No surgery, in either direction: no sail repair, smoothing, remesh, hole fill, shard filtering, base removal, or underside cut. mesh_place.py is the only transform and it does uniform scale, XY centering and Z flooring only.

Independent placement verification

mesh_place.py verifies its own export, so that check could reproduce a producer-side omission. R21 used a separate consumer-side verifier for exactly this reason and R22 does the same: this reads both STLs off disk and derives the comparison itself, without consulting the placement report.

python3 - <<'PY'
import hashlib
import json
import pathlib

import numpy as np
import trimesh

project = pathlib.Path("projects/treeman-windmill")
sources = {
    "a1-m1": "treeman-r20-clay-bright-grokq-m1-raw",
    "a1-m2": "treeman-r20-clay-bright-grokq-m2-raw",
    "a1-m3": "treeman-r20-clay-bright-grokq-m3-raw",
    "a1-m4": "treeman-r20-clay-bright-grokq-m4-raw",
    "a2-m1": "treeman-r20-clay-bright-flash31-m1-raw",
    "a2-m2": "treeman-r20-clay-bright-flash31-m2-raw",
    "a2-m3": "treeman-r20-clay-bright-flash31-m3-raw",
    "a2-m4": "treeman-r20-clay-bright-flash31-m4-raw",
    "a3-m1": "treeman-r20-clay-orig-grokq-m1-raw",
    "a3-m2": "treeman-r20-clay-orig-grokq-m2-raw",
    "a3-m3": "treeman-r20-clay-orig-grokq-m3-raw",
    "a3-m4": "treeman-r20-clay-orig-grokq-m4-raw",
}
failures = []
for case, source in sorted(sources.items()):
    src_path = project / f"models/round-20/{source}.stl"
    out_path = project / f"models/round-22/treeman-r22-{case}-50mm.stl"
    # process=False for the coordinate comparison: the STL's exact triangles,
    # unmerged. process=True for topology, where an unmerged soup would report
    # one component per triangle and make the component check vacuous.
    src = trimesh.load(src_path, force="mesh", process=False)
    out = trimesh.load(out_path, force="mesh", process=False)
    src_topo = trimesh.load(src_path, force="mesh", process=True)
    out_topo = trimesh.load(out_path, force="mesh", process=True)
    # Derive the PRESCRIBED transform from the SOURCE alone. Aligning the
    # expectation to the output's own minimum would only recover whatever
    # offset the producer applied, so a consistently wrong translation would
    # verify against itself.
    scale = 50.0 / (src.bounds[1][2] - src.bounds[0][2])
    scaled_low = src.bounds[0] * scale
    scaled_high = src.bounds[1] * scale
    translation = np.array([
        -(scaled_low[0] + scaled_high[0]) / 2.0,
        -(scaled_low[1] + scaled_high[1]) / 2.0,
        -scaled_low[2],
    ])
    expected = np.asarray(src.triangles) * scale + translation
    # The artifact's OWN displacement, observed rather than prescribed. Used
    # only to bind the report to the mesh, never as the expectation.
    displacement = (
        np.asarray(out.triangles).reshape(-1, 3)
        - np.asarray(src.triangles).reshape(-1, 3) * scale
    )
    actual_translation = displacement.mean(0)
    # rtol=0: np.allclose's default 1e-5 relative term would accept roughly
    # 0.0006mm of error at a 50mm coordinate, so the stated absolute limit
    # would not actually be enforced.
    max_error = (
        float(np.abs(out.triangles - expected).max())
        if out.triangles.shape == expected.shape
        else float("inf")
    )
    checks = {
        "triangle count": len(out.faces) == len(src.faces),
        "coordinates within 0.0001mm": max_error <= 1e-4,
        "height 50.00mm": abs((out.bounds[1][2] - out.bounds[0][2]) - 50.0) <= 1e-4,
        "floored at z=0": abs(out.bounds[0][2]) <= 1e-4,
        "xy centred": np.allclose(out.bounds.mean(axis=0)[:2], 0.0, atol=1e-4),
        "shards preserved": out_topo.body_count == src_topo.body_count,
        "winding preserved": (
            out_topo.is_winding_consistent == src_topo.is_winding_consistent
        ),
        "watertightness preserved": out_topo.is_watertight == src_topo.is_watertight,
    }
    # The placement REPORT is provenance and is checked too: a correct mesh with
    # a wrong declared scale, translation or digest would otherwise leave the
    # round with false placement provenance and every other gate passing.
    report = json.loads(
        (project / f"notes/r22-{case}-placement.json").read_text()
    )
    src_digest = hashlib.sha256(src_path.read_bytes()).hexdigest()
    out_digest = hashlib.sha256(out_path.read_bytes()).hexdigest()
    checks.update({
        "report scale": abs(report["scale"] - scale) <= 1e-9,
        "report target height": report["target_height_mm"] == 50.0,
        "report operation": report["operation"] == "uniform-scale-center-xy-floor-z",
        "report source digest": report["source_sha256"] == src_digest,
        "report output digest": report["output_sha256"] == out_digest,
        # Full paths, not suffixes: the right basename under the wrong
        # directory would otherwise leave false provenance in the record.
        "report source path": report["source"] == str(src_path),
        "report output path": report["output"] == str(out_path),
        # Subscripted, never .get(): a missing key must raise, not silently
        # satisfy the check against a default derived from the same data.
        # Three checks, because two of them alone leave a gap either way. The
        # report must match the PRESCRIBED transform (catches a producer that
        # applies and reports the same wrong offset) AND match the ARTIFACT's
        # actual displacement (catches a producer that shifts the mesh but
        # writes the correct translation). The 1e-4 affine tolerance above
        # would admit either on its own.
        "report translation matches prescribed": np.allclose(
            np.asarray(report["translation_mm"]), translation, rtol=0, atol=1e-6
        ),
        # 1e-5, not 1e-6: STL stores float32, so a correct placement still
        # shows ~2e-6mm of per-vertex spread at 50mm coordinates (float32 eps
        # there is ~6e-6mm). Measured on a real placement before choosing it.
        "displacement is a pure translation": (
            float(np.abs(displacement - actual_translation).max()) <= 1e-5
        ),
        "report translation matches the artifact": (
            float(np.abs(actual_translation - np.asarray(report["translation_mm"])).max())
            <= 1e-5
        ),
        "report faces": report["faces"] == len(out.faces),
        "report watertight": report["watertight"] == out_topo.is_watertight,
        "report winding": (
            report["winding_consistent"] == out_topo.is_winding_consistent
        ),
        "report output extents": np.allclose(
            np.asarray(report["output_extents_mm"]),
            out.bounds[1] - out.bounds[0],
            rtol=0,
            atol=1e-6,
        ),
    })

    bad = [name for name, ok in checks.items() if not ok]
    print(f"{case}: max coord error {max_error:.7f}mm  "
          f"{'OK' if not bad else 'FAIL ' + ', '.join(bad)}")
    if bad:
        failures.append((case, bad))
if failures:
    raise SystemExit(f"independent placement verification failed: {failures}")
PY

A failure here fails the round. Shards are asserted PRESERVED, not filtered: shards preserved compares merged component counts, so it fails if a placement silently dropped one of the 1–4 face shards the R20 sources carry.

The placement REPORT is verified alongside the mesh, since it is the round's placement provenance and nothing else reads it: the declared scale, target height, operation, translation, output extents, source path, output path and both SHA-256 digests are re-derived here and compared. A correct mesh carrying a wrong declared scale or digest would otherwise pass every other gate.

Verified against a real mesh_place.py run on a torus-plus-shard fixture: the checks pass on a correct placement, shards preserved reads 2 against 2 on the merged meshes, and nudging a single output vertex by 0.01 mm trips the coordinate check.

Main-shell topology comparison

The runbook requires each output's main-shell edge topology to match its source, and a change there fails the round. mesh_validate.py writes the output record but compares it with nothing, so that condition would otherwise live only in prose. Applicability gate, before any comparison is drawn

mesh_handles.py asserts no validity verdict, so the round applies its own. This runs after all sixteen handle reports exist and before the arm-level comparison; a non-zero exit stops the round.

python3 - <<'PY'
import json
import pathlib
import statistics

reports = sorted(
    pathlib.Path("projects/treeman-windmill/notes/r22-handles").glob("*.json")
)
assert len(reports) == 16, f"expected 16 handle reports, found {len(reports)}"
ratios = {}
for path in reports:
    data = json.loads(path.read_text())
    ratios[data["label"]] = data["fill_ratio"]

# Third condition, independent of the probe: every MEASURED mesh must have a
# closed dominant shell in its own validation record. These are the twelve R22
# placed outputs the handle reports were produced from — not the R20 sources,
# whose records would stay clean if placement or export opened an output shell —
# plus the four references, which are not re-placed and so use their own frozen
# records.
notes = pathlib.Path("projects/treeman-windmill/notes")
records = {}
for path in sorted((notes / "r22-mesh-validation").glob("*.json")):
    records[json.loads(path.read_text())["label"]] = path
for stem in ("r19-a1-m12", "r19-a3-m6", "r21-a1-m2", "r21-a2-m8"):
    path = notes / f"{stem}-validation.json"
    records[json.loads(path.read_text())["label"]] = path
assert len(records) == 16, f"expected 16 validation records, found {len(records)}"
# Bind the two sets: every measured mesh must have a record and vice versa.
missing = sorted(set(ratios) ^ set(records))
assert not missing, f"handle reports and validation records disagree: {missing}"

median = statistics.median(ratios.values())
failures = []
for label, ratio in sorted(ratios.items()):
    reasons = []
    if ratio <= 5.0:
        reasons.append(f"fill_ratio {ratio} <= 5.0 floor (a leaked fill reads 1.0)")
    if ratio < median / 2:
        reasons.append(f"fill_ratio {ratio} below half the set median {median}")
    print(f"{label}: fill_ratio {ratio}"
          + (f"  FAIL: {'; '.join(reasons)}" if reasons else ""))
    if reasons:
        failures.append((label, reasons))

for label, path in sorted(records.items()):
    open_edges = json.loads(path.read_text())["mesh"]["main_component_open_edges"]
    if open_edges != 0:
        print(f"{label}: main_component_open_edges {open_edges}  FAIL")
        failures.append((label, [f"main_component_open_edges {open_edges} != 0"]))

if failures:
    raise SystemExit(f"applicability gate failed: {failures}")
print(f"applicability gate: OK (16 records, median fill_ratio {median})")
PY

The third condition reads validation records rather than the probe, so it is independent of everything above, and it EXECUTES rather than being asserted in prose. It reads the records of the meshes actually MEASURED — the twelve R22 placed outputs, not the R20 sources — so an output whose shell opened during placement or export cannot hide behind a clean source record. The symmetric difference assertion binds the two sets, so a missing or surplus report on either side is an error rather than a silently skipped mesh. Record the gate's output in rounds.md whether it passes or fails.

Those reference reports are new R22 evidence about frozen R19/R21 artifacts. They are written under r22-handles/ and appended as R22 comparison-evidence records; no R19 or R21 record, report, or artifact is edited.
