How the round is judged

All checks are FAST (local, deterministic, or a fresh-context subagent):

  • Raw side re-verified from Drive: the canonical STL's SHA-256 must match the frozen R9 raw_validation record before any edit.
  • Bounded cleanup, declared here: remove exactly the two one-face satellite components (component faces 855,386 + 1 + 1; the main shell is independently watertight with zero open and zero non-manifold edges) after the standard position/size look confirms they are debris, and weld coincident vertices. Nothing else: no bridging, cutting, boolean work, sculpting, or repositioning. Anything more stops for a separately approved mesh-surgery round.
  • Finishing: scale to 24 mm figure height (top of head), XY-center, floor z=0; the raw provider file stays untouched and the clean mesh is a new trumbert-r9-g14-m2-clean lineage artifact (append-only; the frozen raw record is not rewritten).
  • Full final-scale battery: watertightness/Euler/winding on the clean mesh, dimensions/volume sanity, surface roughness, mesh_thin_parts.py at the tight resin setting (pitch ~0.28, erode 1) with the ankh, scimitar blade/tip and ears as named risk regions, internal-void cross-sections, base-contact check, and clean stats recorded via mesh_stats.py. (Meshy's free Analyze Printability endpoint stays in docs/experiments-backlog.md as a future idea — no repository tool calls it yet, so it is NOT part of this round's evidence.)
  • Renders + audit: default eight-view montage plus ankh, shield-strap, hands and ground zooms; a fresh-context subagent runs the standard per-feature comparison against the g14 source sheet (ankh and shield straps first — Dimitri's two pin-down features from the R9 feedback — then scimitar shape/grip, digit count, shield, sunburst, cloak, ears, feet/ground contact, phantom geometry).
  • Human gate: Dimitri's live-3D look at the finished mesh via the r10-panel viewer decides whether it is a print candidate or the baseline r11 must beat.

Process riders (records-only, no spend, no Discord posting — details in the technical block): R10 is proposed as the #434 repository-only lifecycle pilot, and its gate/lifecycle store merges will produce the pipeline-source Discord wakeup runtime proof issue #287 is waiting on.
